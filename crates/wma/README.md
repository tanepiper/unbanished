# banished-wma

A pure-Rust decoder for Windows Media Audio v2 (format tag `0x161`), the codec inside the xWMA
files that Banished ships as `SoundBuffer` resources. It has no dependencies and no `unsafe`, and
it builds for `wasm32-unknown-unknown`, so the browser build can decode the user's own game data
without FFmpeg.

```rust
let params = banished_wma::Params::xwma(channels, sample_rate, avg_bytes_per_sec, block_align);
let pcm: Vec<i16> = banished_wma::decode(&params, packets)?; // interleaved
```

For streamed music, create a `Decoder`, call `decode_packet` once per `block_align`-byte packet
(it appends interleaved `f32` samples), and call `flush` at the end. The decoder drops the
codec's two-frame start-up delay (`Decoder::delay()`), as FFmpeg does. The output therefore lines
up sample-for-sample with FFmpeg's and has the same length.

## Scope

Supported: WMA v2, mono and stereo, all sample rates, variable block lengths, bit reservoir,
M/S stereo, VLC-coded exponents, and noise substitution for high bands.

Not supported: WMA v1 (`0x160`), LSP-coded exponents (streams without flag bit 0), WMA Pro,
Lossless and Voice. xWMA files carry no codec extradata, so `Params::xwma` uses the encoder
flags they imply (`XWMA_FLAGS = 0x1f`).

The noise-substitution path is implemented but **untested**: at Banished's bitrate (48 kbit/s)
the encoder never enables it, so none of the shipped sounds exercise it.

## Verification

`tests/ffmpeg_parity.rs` decodes every `SoundBuffer` in `game-data/original/WinData` and compares
the result with FFmpeg's `wmav2` decoder, using FFmpeg's float output so that its
platform-specific s16 conversion does not affect the comparison. The test is skipped if the game
data or `ffmpeg` is missing. On all 72 shipped sounds, sample counts match exactly and SNR is
at least 125 dB (the pass threshold is 60 dB).

```sh
cargo test -p banished-wma --release -- --nocapture
```

## Licence and provenance

The crate is licensed `MIT OR Apache-2.0`, like the rest of the workspace. Its decoder code was
written from scratch for this project and is not a port of FFmpeg's LGPL `wmadec.c`. FFmpeg is
used only as an external test oracle. WMA has no public specification, so the bitstream
structure follows the publicly known layout of the format.

`src/tables.rs` holds the codec's constant tables (VLC codewords, run/level maps, band edges).
Every compatible decoder must reproduce these exactly. They are taken from the MIT-licensed
[`oxideav-wma`](https://crates.io/crates/oxideav-wma) 0.0.4 crate, which documents them as
extracted from the vendor decoder's data sections. They are regenerated by
`tools/gen-wma-tables.py`. The MIT notice is reproduced in [THIRD_PARTY.md](THIRD_PARTY.md).
