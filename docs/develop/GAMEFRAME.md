# Un-Banished and GameFrame

[GameFrame](https://github.com/tanepiper/game-frame) is the framework that grew out of this
project: the method, the skills, the agents and the tools, made generic for any game. This page
compares Un-Banished with GameFrame's standard for a project (its project template, rules, labels,
agents, gates and tools, as of October 2026). It lists what already matches, what was brought up
to the standard, and what is still to decide. The comparison and the tool runs were made on
2026-10-22.

## What already matches

| GameFrame's standard | In Un-Banished |
|---|---|
| Rules for agents: evidence labels, game material out of git, staging only your own files | [AGENTS.md](../../AGENTS.md), with the same rules in the project's own words |
| Every ported item cites its original function | Doc comments end with ``Original: `FUN_…` ``; `tools/triage/coverage.py` measures them |
| A ledger of deviations | [DEVIATIONS.md](../DEVIATIONS.md), regenerated by the quick test tier |
| Labels for functions and fields | `tools/triage/names.tsv` and `tools/triage/fields.tsv`, with the same columns as GameFrame's `labels/names.tsv` and `labels/fields.tsv` |
| An overview and a checklist | [FINDINGS.md](../FINDINGS.md) and [GAME-LOOP-CHECKLIST.md](../GAME-LOOP-CHECKLIST.md) |
| A skill for each step of the method | The `banished-*` skills in `.claude/skills/`, one for each of GameFrame's `re-*` steps that this game needs |
| An exact core with additions kept apart | `crates/sim` has no drawing, sound, window or network; extensions are cargo features, and `--vanilla` turns them off ([Extensions](EXTENSIONS.md)) |
| One chosen version of the game | Banished 1.0.7, Steam build 170910, Windows x64 ([AGENTS.md](../../AGENTS.md)) |
| Fixity of the game copy | `game-data/MANIFEST.sha256` |
| Whole-system checks: saves, frames, versions | [Compatibility](../COMPATIBILITY.md), the probe baselines and `tools/compat/` |

## What GameFrame's newer tools found

GameFrame's tools were run on Banished's files. The results are recorded where they belong:

- **Type ids** (`hashnames.py`). With no hint, it found that type ids are CRC-32 hashes of UTF-16
  class names, and named 169 of the 170 registered types from the data alone
  ([GAME-TYPE-REGISTRATION-FINDINGS.md](../GAME-TYPE-REGISTRATION-FINDINGS.md)).
- **Shader source** (`shaders.py`). 31 materials carry GLSL 3.3 source, generated from the
  engine's own shading language, beside the Direct3D 9 and 11 bytecode. This was not recorded
  before. It is a second reference when a shader is ported ([Port a shader](guides/SHADER.md)).
- **Skeletons** (`skeleton.py`). It finds the citizen's 27 bones in the mesh resources, named
  from their records, and the animation keys in `CitizenAnims_resource.crs`. This confirms the
  reader in `crates/formats/src/types.rs`.

Running the tools on Banished also improved them. Each fix went into GameFrame with a test:
hashes found only in data files, small type ids, bones stored as records, and labels made from a
port's citations.

## Brought up to the standard

- **Labels from the port's citations.** The port cites about 2,000 original functions, but only
  226 had labels, so the decompiled code that sessions read still said `FUN_…` for most of them.
  `tools/triage/cite_labels.py` (from GameFrame) now reads the citations and writes
  `tools/triage/names-from-port.tsv`: 477 more labels, named after the Rust item that cites each
  function. `decomp.py` and `fnindex.py` read it after `names.tsv`, and a label written by hand
  always wins. Labelled code in the Application binary rose from 10.2 % to 28.2 % by size. The
  quick test tier regenerates the file and fails when it was out of date, as it does for the
  deviations ledger.

## Still to decide

| Gap | Choices |
|---|---|
| **Gates.** GameFrame installs hooks that stop a command from adding game material, decompiled code or another session's files to git (`scripts/hooks/gate.py`, [gates](https://tanepiper.github.io/game-frame/working/gates)). Un-Banished relies on `.gitignore` and the rules in AGENTS.md | Install the gates in `.claude/settings.json`; or keep the rules as they are |
| **Agents.** GameFrame has 18 agents (nine stages and nine tasks) that hand work to each other. Un-Banished has skills only | Install GameFrame as a Claude Code plugin, so its agents are available here; or copy the agents and point them at the `banished-*` skills |
| **Where the labels live.** GameFrame's tools look for `labels/names.tsv` in the project. Un-Banished keeps them in `tools/triage/` | Move them to `labels/` and update the tools; or pass `--labels` to GameFrame's tools |
| **Citations with no item after them.** 542 citations sit in module comments or inside function bodies, so no label is made for them | Move each citation onto the item that ports the function, where there is one |
| **Structures.** `fields.tsv` names 143 fields. GameFrame's `decomp_query.py layout` builds a structure's fields from all the functions that use it | Run it on the main classes (Citizen, Building, Storage) and add the fields with evidence |
| **Diagrams.** GameFrame's guides now have a diagram for each topic | Add diagrams to the topic pages here, made the same way (`site/diagrams/` in GameFrame) |

## How to run GameFrame's tools here

Clone GameFrame next to this repository, then run its tools from this folder:

```bash
GF=../game-frame
python3 $GF/tools/triage/hashnames.py game-data/extracted --aligned \
  --names-from game-data/original/Application-steam-x64.exe --names-from game-data/original/Runtime-steam-x64.dll
python3 $GF/tools/formats/shaders.py game-data/extracted/Material/Weather/WeatherMaterial_Normal_ps.crs
python3 $GF/tools/formats/skeleton.py game-data/extracted/Models/Citizen/CitizenMaleMesh_resource.crs
python3 $GF/tools/triage/decomp_query.py --export analysis/export --binary Application-steam-x64.exe \
  --labels tools/triage/names.tsv --labels tools/triage/names-from-port.tsv stats
```

Their output describes the game's files. Keep it in `analysis/` or `derived/`, never in git.
