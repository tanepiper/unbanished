# Un-Banished and GameFrame

[GameFrame](https://github.com/tanepiper/game-frame) is the framework that grew out of this
project: the method, the skills, the agents and the tools, made generic for any game. This page
compares Un-Banished with GameFrame's standard for a project (its project template, rules, labels,
agents, gates and tools, as of October 2026). It lists what already matched, what GameFrame's
tools found in the game's files, and what was changed to meet the standard. The comparison and
the tool runs were made on 2026-10-22.

## What already matched

| An overview | [FINDINGS.md](../FINDINGS.md) |

| An exact core with additions kept apart | `crates/sim` has no drawing, sound, window or network; extensions are cargo features, and `--vanilla` turns them off ([Extensions](EXTENSIONS.md)) |
| One chosen version of the game | Banished 1.0.7, Steam build 170910, Windows x64 ([AGENTS.md](../../AGENTS.md)) |

| Whole-system checks: saves, frames, versions | [Compatibility](../COMPATIBILITY.md), the probe baselines and `tools/compat/` |

## What GameFrame's newer tools found

GameFrame's tools were run on Banished's files. The results are recorded where they belong:

- **Type ids** (`hashnames.py`). With no hint, it found that type ids are CRC-32 hashes of UTF-16
  class names, and named 169 of the 170 registered types from the data alone
  ([GAME-TYPE-REGISTRATION-FINDINGS.md](../GAME-TYPE-REGISTRATION-FINDINGS.md)).
- **Shader source** (`shaders.py`). 31 materials carry GLSL 3.3 source, generated from the
  engine's own shading language, beside the Direct3D 9 and 11 bytecode. This was not recorded
  before. It is a second reference when a shader is ported ([Port a shader](guides/SHADER.md)).
- **Skeletons** (`skeleton.py`). It finds the citizen's 27 bones in the mesh resources, named
  from their records, and the animation keys in `CitizenAnims_resource.crs`. This confirms the
  reader in `crates/formats/src/types.rs`.

Running the tools on Banished also improved them. Each fix went into GameFrame with a test:
hashes found only in data files, small type ids, bones stored as records, and labels made from a
port's citations.

## Changed to meet the standard

| GameFrame's standard | What changed here |
|---|---|
| Labels for every function the project has identified | `tools/triage/cite_labels.py` (from GameFrame) reads the port's ``Original: `FUN_…` `` citations and writes `labels/names-from-port.tsv`: 477 more labels, named after the Rust item that cites each function. The decompile tools read it after `labels/names.tsv`, so a label written by hand wins. Labelled code in the Application binary rose from 10.2 % to 28.2 % of all its code by size, 703 functions. The quick test tier regenerates the file and fails when it was out of date |
| Library code apart from the game's code | `tools/triage/library.py` names the C runtime, the Steam stub and the unnamed exception funclets in `labels/library.tsv`, from Ghidra's Function ID matches and the link order: 292 functions in the Application and 682 in the Runtime ([LIBRARY-CODE.md](../LIBRARY-CODE.md)) |
| One coverage figure | "Traced" means labelled, in `names.tsv` or `names-from-port.tsv`. `fnindex.py coverage` reports the traced share of the game's own code, with library code apart: 37.9 % of the Application's own code on 2026-10-22 ([CHECKLIST.md](../CHECKLIST.md), "Coverage"). The earlier 68 % counted every function named anywhere in the code or the docs, over all the code |
| Labels in `labels/` | `names.tsv`, `fields.tsv` and `names-from-port.tsv` moved from `tools/triage/` to `labels/`, where GameFrame's tools look. Every tool, skill and guide here was updated |
| GameFrame's skills and agents | `.claude/settings.json` enables GameFrame's Claude Code plugin: its `re-*` skills and its 18 agents. The `banished-*` skills stay the first choice for this game ([AGENTS.md](../../AGENTS.md), "GameFrame") |
| The gates | The plugin's hooks stop a commit or a written file that would add game material or decompiled code. The project's settings also refuse force-adding, `git add -A`, `git add .`, `git commit -a` and force-pushing, as AGENTS.md already required |
| GameFrame's toolkit | `tools/gf.sh` runs any GameFrame tool from this folder, from the machine's one GameFrame checkout (`GAMEFRAME_ROOT` in `.env`) |
| GameFrame's launcher and MCP servers | `./gameframe` is GameFrame's project launcher. The plugin starts GameFrame's MCP server with `./gameframe serve`. REA starts from `.mcp.json` with `./gameframe mcp-provider rea`, at the version GameFrame pins (6.7.0 in October 2026) |
| A checklist in GameFrame's format | [CHECKLIST.md](../CHECKLIST.md) gives the state by inventory, foundations, systems and labels, and links to [GAME-LOOP-CHECKLIST.md](../GAME-LOOP-CHECKLIST.md) for the details. GameFrame's session hook reads its open items |
| Save games out of git | `/save-game/` added to `.gitignore` (`*.sav` was already ignored) |

The project's licences (Apache 2.0 and MIT) are its own choice and stay as they are; GameFrame's
template offers Apache 2.0 and CC0 as defaults, which a project may change. The next
improvements are in [CHECKLIST.md](../CHECKLIST.md), "Labels and evidence".

## How to run GameFrame's tools here

Use the machine's one GameFrame checkout, named in `.env` as `GAMEFRAME_ROOT=/path/to/it`. Do
not clone GameFrame next to this repository: a second clone falls behind. Run its
tools from this folder with `tools/gf.sh`, which sets `GAMEFRAME_PROJECT` to this folder. In the
commands below, `$GF` stands for that checkout, as in the skills:

```bash
tools/gf.sh tools/triage/hashnames.py game-data/extracted --aligned \
  --names-from game-data/original/Application-steam-x64.exe --names-from game-data/original/Runtime-steam-x64.dll
tools/gf.sh tools/formats/shaders.py game-data/extracted/Material/Weather/WeatherMaterial_Normal_ps.crs
tools/gf.sh tools/formats/skeleton.py game-data/extracted/Models/Citizen/CitizenMaleMesh_resource.crs
tools/gf.sh tools/triage/decomp_query.py --export analysis/export --binary Application-steam-x64.exe \
  --labels labels/names.tsv --labels labels/names-from-port.tsv stats
```

Their output describes the game's files. Keep it in `analysis/` or `derived/`, never in git.
